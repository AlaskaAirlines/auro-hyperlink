# AB#1658021

## Executive Summary

Every Auro component publishes a machine-readable "manifest" that describes it: what it is called, what options it has, and what each option does. Documentation sites, design tools, and AI assistants all read this file. The published manifest for `auro-hyperlink` was already correct, but nothing checked that it stayed that way, so a future change could quietly break it and ship without anyone noticing.

This work adds an automatic quality check to the `auro-hyperlink` build. If the manifest breaks the design system's rules, the build now fails instead of publishing a bad file. While in there, we also rewrote the component's descriptions in plain language and documented its customizable colors, so the manifest, and the documentation generated from it, is accurate and readable by non-engineers. The build tooling and several development dependencies were also moved to newer versions.

Ticket: [AB#1658021](https://itsals.visualstudio.com/E_Retain_Content/_workitems/edit/1658021)

## The Problem

The published manifest for `auro-hyperlink` (version 8.0.6) already passed the design system's strict check with zero findings, but nothing enforced it. A change that broke the manifest would only be discovered later, by a consumer.

Separately, a few descriptions in the manifest were wrong or misleading. For example, one internal setting was described as "the language of an element", and the description of how safe web addresses are handled did not match what the component actually does. The manifest also listed none of the component's customizable color properties.

## Root Cause

- `package.json` had `"build": "auro build"` only. `auro build` generates `custom-elements.json` but never validates it against the contract, so no build step could fail on a bad manifest.
- `src/layoutElement/auroElement.js`: the `layout` property was documented as "Defines the language of an element" with `@default 'default'`, which was wrong, and it was exposed as public API instead of internal.
- `src/component-base.mjs`: the `safeUri` getter's JSDoc example returned `'http://example.com'` for an `http` input, but the code upgrades to `https` and normalizes to `'https://example.com/'`. The `@returns` type also omitted `undefined`, which `safeUrl` returns when an address is dropped as unsafe. `href` documented none of the URL-safety behavior.
- `src/auro-hyperlink.js`: `getMarkup()` was documented as returning a CSS class object it does not return, the class description lacked a plain-language summary, slot documentation, and accurate `@csspart` notes, and the class declared no `@cssprop` entries, so none of the component's customizable color properties appeared in the manifest.

## The Fix

- `package.json`: added `"cem:check": "auro cem-check --strict"` and changed `build` to `"auro build && npm run cem:check"`, so a non-zero exit from the check fails the build.
- `package.json` (dependencies): bumped dev dependencies, including `@aurodesignsystem/auro-cli` `^4.0.0` to `^5.1.0`, `@aurodesignsystem/auro-button` `^12.4.0` to `^13.0.0`, `@alaskaairux/icons`, `@aurodesignsystem/auro-library`, and `@aurodesignsystem/design-tokens`. Runtime `dependencies` still contains only `lit`.
- `src/auro-hyperlink.js`: rewrote the class JSDoc (audience-friendly intro that mentions ARIA forwarding, key capabilities, example, `@summary`, `@customElement`, `@forcePrivate {'layout'}`), documented the default `@slot` and both `@csspart`s, added 64 `@cssprop` entries (default, visited, focus, and hover states, each with `nav-` variants, in `default` and `inverse` forms), and corrected the `register`, `renderLayoutDefault`, `renderLayoutCTA` and `getMarkup` comments.
- `src/component-base.mjs`: added `@category` (`ui`, `behavior`) to every public property, `@relevantWhen type !== "cta"` / `type === "cta"` where a property only applies to one link type, quoted `@default` values, and rewrote the public property descriptions in plain language. The `href` description now covers safe-URL handling: `javascript:`, `data:`, and `vbscript:` are dropped, every other address except `tel:`, `sms:`, and `mailto:` is upgraded to `https` unless the page is served from `localhost`. The `rel` description now states that `target="_blank"` links to another site get `noOpener noReferrer`, or `external` when `referrerpolicy` is on. The `safeUri` doc was corrected.
- `src/layoutElement/auroElement.js`: marked `layout` as `@private` with an accurate description, added `@default`, `@category` and `@relevantWhen` tags to `shape` and `size`, quoted `@default` on `appearance`, and rewrote the `appearance`, `shape` and `size` descriptions.
- `docs/api.md` regenerates from the manifest during the build and now includes a Slots section; the same wording changes were applied to it by hand and its table padding will realign on the next docs build.

## Why This Works

- `auro cem-check --strict` treats any finding as a failure, and `&&` in the `build` script propagates that exit code, so CI and local builds both stop on a bad manifest.
- The check validates the manifest after `auro build` has generated it, so it always inspects the file that will actually be published.
- Marking `layout` with both `@forcePrivate {'layout'}` on the class and `@private` on the property keeps it out of the public attribute and member lists, matching the design system contract.
- The `@cssprop` names, the ARIA forwarding claim, the `type="cta"` "ignored" notes, and the `safeUrl`/`safeUri`/`includesDomain` behavior were each checked against the code during review (all 64 property names exist in `src/styles`; `firstUpdated` forwards ARIA attributes to the inner link; `download`, `referrerpolicy` and `role` are not passed to the internal button).
- The block-tag forms of `@category` and `@relevantWhen` are used (not the inline `{@...}` forms) because the inline forms leak into the generated docs as literal text.

## Outcome

- The `auro-hyperlink` build now fails if its manifest breaks the design system's rules.
- The component's published description, option list, slot, style-part, and customizable color notes are accurate and written in plain language.
- The locally generated `custom-elements.json` contains 56 `category` values, 28 `relevantWhen` entries, and 64 `--ds-auro-hyperlink-*` CSS properties.
- Earlier in this work, the strict check reported no violations, 54 of 54 tests passed, and `npm pack --dry-run` listed `custom-elements.json` (52.5 kB). Those results came from a working tree using unreleased dev builds of `auro-cli` and `auro-button`, and have not been re-run against the published `auro-cli` 5.1.0 and `auro-button` 13 the branch now depends on.

## Learnings

- Strict CEM checking costs almost nothing to add when the manifest is already clean, and it turns a silent regression into a build failure. Add it to every component's `build` script.
- `@category`, `@relevantWhen`, `@requiredWhen` and `@minimum` were not processed by published `auro-cli` releases 4.0.0, 4.1.0 and 5.0.0. The dev build `0.0.0-pr344.0` does process them. Whether `5.1.0` does has not been verified; rebuild and count `category` and `relevantWhen` entries in `custom-elements.json` to confirm. Until then, treat the block tags as possibly inert but harmless.
- Use block tags, not inline `{@category ...}` / `{@relevantWhen ...}` tags, in slot and `@property` descriptions. The inline forms appear as literal text in `custom-elements.json` and `docs/api.md`.
- `@forcePrivate {'layout'}` on the class, plus `@private` on the property, is how an inherited internal property is kept out of the public contract.
- When JSDoc examples show a return value, run the code to confirm it. The old `safeUri` example was wrong because `safeUrl` upgrades to `https` and normalizes the URL.
- Check doc claims against the code's real conditions, not just its common case. `safeUrl` upgrades every protocol except `tel:`, `sms:`, `mailto:` and the three dropped ones (including `ftp:` and `file:`), and skips the upgrade based on the page URL, not the `href`. `getRelType` returns `external`, not `noOpener noReferrer`, when `referrerpolicy` is on.
- **Before this ships:** `README.md` still carries an unintended edit from `a2f5c89` that replaced a line break with `&#10;` and altered an invisible character in the install snippet; it does not belong to this change. The untracked `figma/` directory (generated mismatch and translate reports) also should not be committed with this work. Dev-build `auro-cli` and `auro-button` references and the stray `install` and `npm` entries in `dependencies` have been removed from `package.json`.
