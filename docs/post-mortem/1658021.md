# AB#1658021

## Executive Summary

Every Auro component publishes a machine-readable "manifest" that describes it: what it is called, what options it has, and what each option does. Documentation sites, design tools, and AI assistants all read this file. The published manifest for `auro-hyperlink` was already correct, but nothing checked that it stayed that way, so a future change could quietly break it and ship without anyone noticing.

This work adds an automatic quality check to the `auro-hyperlink` build. If the manifest breaks the design system's rules, the build now fails instead of publishing a bad file. While in there, we also tightened up the component's descriptions so the manifest, and the documentation generated from it, is accurate and readable by non-engineers.

Ticket: [AB#1658021](https://itsals.visualstudio.com/E_Retain_Content/_workitems/edit/1658021)

## The Problem

The published manifest for `auro-hyperlink` (version 8.0.6) already passed the design system's strict check with zero findings, but nothing enforced it. A change that broke the manifest would only be discovered later, by a consumer.

Separately, a few descriptions in the manifest were wrong or misleading. For example, one internal setting was described as "the language of an element", and the description of how safe web addresses are handled did not match what the component actually does.

## Root Cause

- `package.json` had `"build": "auro build"` only. `auro build` generates `custom-elements.json` but never validates it against the contract, so no build step could fail on a bad manifest.
- `src/layoutElement/auroElement.js`: the `layout` property was documented as "Defines the language of an element" with `@default 'default'`, which was wrong, and it was exposed as public API instead of internal.
- `src/component-base.mjs`: the `safeUri` getter's JSDoc example returned `'http://example.com'` for an `http` input, but the code upgrades to `https` and normalizes to `'https://example.com/'`. The `@returns` type also omitted `undefined`, which `safeUrl` returns when an address is dropped as unsafe. `href` documented none of the URL-safety behavior.
- `src/auro-hyperlink.js`: `getMarkup()` was documented as returning a CSS class object it does not return, and the class description lacked a plain-language summary, slot documentation, and accurate `@csspart` notes.

## The Fix

- `package.json`: added `"cem:check": "auro cem-check --strict"` and changed `build` to `"auro build && npm run cem:check"`, so a non-zero exit from the check fails the build.
- `src/auro-hyperlink.js`: rewrote the class JSDoc (audience-friendly intro, key capabilities, example, `@summary`, `@customElement`, `@forcePrivate {'layout'}`), documented the default `@slot` and both `@csspart`s, and corrected the `register`, `renderLayoutDefault`, `renderLayoutCTA` and `getMarkup` comments.
- `src/component-base.mjs`: added `@category` (`ui`, `behavior`) to every public property, `@relevantWhen type !== "cta"` / `type === "cta"` where a property only applies to one link type, quoted `@default` values, a rewritten `href` description covering safe-URL handling, and a corrected `safeUri` doc.
- `src/layoutElement/auroElement.js`: marked `layout` as `@private` with an accurate description, added `@default`, `@category` and `@relevantWhen` tags to `shape` and `size`, and quoted `@default` on `appearance`.
- Descriptions that were already accurate (`appearance`, `download`, `fluid`, `ondark`, `onDark`, `referrerpolicy`, `rel`, `target`, `type`, `variant`, `shape`, `size`) keep their original wording; only the metadata tags were added.
- `docs/api.md` regenerates from the manifest during the build and now includes a Slots section.

## Why This Works

- `auro cem-check --strict` treats any finding as a failure, and `&&` in the `build` script propagates that exit code, so CI and local builds both stop on a bad manifest.
- The check validates the manifest after `auro build` has generated it, so it always inspects the file that will actually be published.
- Marking `layout` with both `@forcePrivate {'layout'}` on the class and `@private` on the property keeps it out of the public attribute and member lists, matching the design system contract.
- Property descriptions were only rewritten where the old text was inaccurate or incomplete; where it was already correct the wording was left alone to keep the diff and documentation churn small.
- The block-tag forms of `@category` and `@relevantWhen` are used (not the inline `{@...}` forms) because the inline forms leak into the generated docs as literal text.

## Outcome

- The `auro-hyperlink` build now fails if its manifest breaks the design system's rules, and it currently passes with zero violations.
- The component's published description, option list, and slot and style-part notes are accurate and written in plain language.
- All 54 existing tests pass and `custom-elements.json` is included in the published package.

## Learnings

- Strict CEM checking costs almost nothing to add when the manifest is already clean, and it turns a silent regression into a build failure. Add it to every component's `build` script.
- `@category`, `@relevantWhen`, `@requiredWhen` and `@minimum` are not processed by published `auro-cli` releases up to 5.0.0 (4.0.0, 4.1.0 and 5.0.0 were checked). The dev build `0.0.0-pr344.0` does process them (56 `category` values and 28 `relevantWhen` entries land in the manifest). With a published CLI the block tags are silently ignored, so they are harmless but inert.
- Use block tags, not inline `{@category ...}` / `{@relevantWhen ...}` tags, in slot and `@property` descriptions. The inline forms appear as literal text in `custom-elements.json` and `docs/api.md`.
- `@forcePrivate {'layout'}` on the class, plus `@private` on the property, is how an inherited internal property is kept out of the public contract.
- When JSDoc examples show a return value, run the code to confirm it. The old `safeUri` example was wrong because `safeUrl` upgrades to `https` and normalizes the URL.
- Only rewrite descriptions that are wrong or incomplete; accurate originals should be kept to limit churn.
- **Before this ships:** the working tree currently has `@aurodesignsystem/auro-cli` pointing at `npm:@aurodesignsystem-dev/auro-cli@0.0.0-pr344.0` and `@aurodesignsystem/auro-button` at `@aurodesignsystem-dev/auro-button@^0.0.0-pr431.1`. These are unreleased dev builds and should be swapped back to published versions. The working tree also has stray `install` and `npm` entries in `dependencies`, a regenerated `package-lock.json`, and a `README.md` edit that replaced a line break with `&#10;` and altered an invisible character, none of which belong to this change.
